Factory orchestration is a new category of product, about it is there are three pillars to factory orchestration. And the goal of these pillars are to simply automate non-productive work so that you have more productive time from operators, therefore you make more parts, and to prevent mistakes that lead to scrap, resulting in less scrap in the shop floor. Two things that who doesn't want to do those two things, right? Anyone who owns a factory presumably wants to do them, but the way factory orchestration works is in unique ways. So the three pillars are number one, automation. We automate non-productive time using technologies like RFID. So you put RFID tags on operator badges, on the jobs that they work on. But the key now have the context of what you're doing. So the second pillar of Harmoni, that was one example of an automation. We have a dozen plus different automations like that that cut out non-productive time. Then once we have that context of who you are, what you're working on, what machine you're at, we use it to power our second pillar, which is process control. And so we're able to pull the correct work instructions and the correct program to run on the equipment that you're running on and the correct check sheet to take all the in-process measurements during the operation The whole goal of the process control pillar is to prevent mistakes from somebody reading an outdated instruction that might be floating around the shop floor or using an old program that might be on a USB stick that operator has. And so with Harmoni, they're getting the latest rev-controlled version of all this information, communicating any changes to the operator that might need to be communicated to prevent scrap from happening in that operation. And the third pillar of factory orchestration is observability, which simply means you know what's going on in your factory. factory that's a lot harder than it sounds.
